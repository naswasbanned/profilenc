==============================================================================
PROFILE PORTFOLIO & CMS - FULL DOCKER DEPLOYMENT INSTRUCTIONS
==============================================================================

[ PREREQUISITES ]
- Docker and Docker Compose installed on your host/server.
- Ensure ports 80 (HTTP) and 3001 (Backend, optional if proxied via nginx) are open.

------------------------------------------------------------------------------
STEP 1: CLONE THE REPOSITORY TO YOUR SERVER
------------------------------------------------------------------------------
On your server/home server:

1. Clone your repo:
   git clone <YOUR_GIT_REPOSITORY_URL> profile

2. Navigate into the cloned folder:
   cd profile

(Note: You DO NOT need Node.js or npm installed on your server host machine.
Docker builds all dependencies inside containers automatically).

------------------------------------------------------------------------------
STEP 2: CREATE AND CONFIGURE YOUR .env FILE
------------------------------------------------------------------------------
Copy the example environment file:
  cp .env.example .env

Edit the .env file with your preferred credentials:
  nano .env

Example .env configuration:
----------------------------------------
DB_PASSWORD=your_secure_db_password_here
JWT_SECRET=your_super_secret_jwt_random_string_here
ADMIN_USERNAME=admin
ADMIN_PASSWORD=your_admin_login_password_here
----------------------------------------

----------------------------------------------
STEP 3: START DOCKER CONTAINERS
------------------------------------------------------------------------------
Build and start the services (db, backend, frontend) in the background:
  sudo docker compose up -d --build

Verify that all 3 containers are running healthy:
  sudo docker compose ps

------------------------------------------------------------------------------
STEP 4: RUN DATABASE MIGRATIONS
------------------------------------------------------------------------------
Create the required PostgreSQL tables (content, images, admin_user):
  sudo docker compose exec backend node src/db/migrate.js

Expected output:
  ✓ content table
  ✓ images table
  ✓ admin_user table
  Migrations complete.

------------------------------------------------------------------------------
STEP 5: SEED INITIAL DATA AND OPTIMIZE IMAGES
------------------------------------------------------------------------------
Populate all 15 JSON datasets and process/compress 27 images to WebP into DB:
  sudo docker compose exec backend node src/db/seed.js

Expected output:
  === Seeding database ===
  1. Loading JSON data...
     ✓ profile.json
     ✓ dev-skills.json
     ... (all 15 datasets)
  2. Collecting image paths...
     Found 27 unique image paths
  3. Processing images → WebP...
     ✓ /images/... -> /uploads/xxxx.webp
  4. Inserting content into database...
  5. Creating admin user...
     ✓ Admin user "admin" created
  === Seed complete ===

------------------------------------------------------------------------------
STEP 6: ACCESS YOUR APPLICATION
------------------------------------------------------------------------------
- Main Portfolio Website:
    http://YOUR_SERVER_IP/  (or http://localhost/ if local)

- Admin CMS Dashboard:
    http://YOUR_SERVER_IP/admin

Log in using the ADMIN_USERNAME and ADMIN_PASSWORD configured in your .env.

==============================================================================
SAFE UPDATES & MAINTENANCE (HOW NOT TO LOSE YOUR DATA)
==============================================================================

When you edit your portfolio via the /admin panel, your data is saved inside
persistent Docker volumes:
  - Database text/data -> "pgdata" volume
  - Uploaded WebP images -> "uploads" volume

HOW TO SAFELY UPDATE YOUR CODE:
--------------------------------
1. Pull new code from git:
     git pull

2. Rebuild and restart containers:
     sudo docker compose up -d --build

3. If there are new database tables or structural schema changes:
     sudo docker compose exec backend node src/db/migrate.js

   (migrate.js uses "CREATE TABLE IF NOT EXISTS" - it is safe and will NEVER
   wipe or overwrite your existing data!)

   *** CRITICAL: DO NOT RUN seed.js AGAIN AFTER INITIAL SETUP ***
   Running seed.js will overwrite your customized data with default JSONs.

==============================================================================
BACKUP & RESTORE PROCEDURES
==============================================================================

[ CREATING A BACKUP ]

1. Backup PostgreSQL Database:
     sudo docker compose exec db pg_dump -U profile profile > db_backup_$(date +%F).sql

2. Backup Uploaded Images:
     sudo docker compose cp backend:/app/uploads ./uploads_backup_$(date +%F)

3. Backup Environment Credentials:
     cp .env .env.backup

[ RESTORING FROM BACKUP ]

1. Restore Database:
     cat db_backup_YYYY-MM-DD.sql | sudo docker compose exec -T db psql -U profile profile

2. Restore Images:
     sudo docker compose cp ./uploads_backup_YYYY-MM-DD/. backend:/app/uploads/

==============================================================================
OTHER USEFUL COMMANDS
==============================================================================

View live logs:
  sudo docker compose logs -f

Restart all containers:
  sudo docker compose restart

Stop all containers:
  sudo docker compose down

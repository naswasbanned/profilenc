==============================================================================
PROFILE & CMS PLATFORM - FULL DOCKER DEPLOYMENT INSTRUCTIONS (MULTI-USER)
==============================================================================

[ PREREQUISITES ]
- Docker and Docker Compose installed on your host/server.
- WSL (if developing on Windows) or native Linux/macOS terminal.
- Ensure port 80 (HTTP) or your custom port is open.

------------------------------------------------------------------------------
STEP 1: CONFIGURE YOUR .env FILE
------------------------------------------------------------------------------
Copy example environment file (if not created):
  cp .env.example .env

Edit .env file:
  nano .env

Configuration keys:
----------------------------------------
DB_PASSWORD=your_secure_db_password_here
JWT_SECRET=your_super_secret_jwt_random_string_here
ADMIN_USERNAME=admin
ADMIN_PASSWORD=your_admin_login_password_here
----------------------------------------

------------------------------------------------------------------------------
STEP 2: START DOCKER CONTAINERS
------------------------------------------------------------------------------
Build and start services (db, backend, frontend):
  sudo docker compose up -d --build

(Note: Database migrations and template seeding run AUTOMATICALLY on startup
with built-in retry mechanism).

Check container status:
  sudo docker compose ps

Check backend logs to verify database init:
  sudo docker compose logs backend

Expected log output:
  Running database migrations...
    ✓ All database tables and indexes verified.
  Seeding templates...
    ✓ 5 template presets seeded.
  Checking legacy data migration to multi-user...
    ✓ Data migration check complete.
  Backend running on http://localhost:3001

------------------------------------------------------------------------------
STEP 3: (OPTIONAL) INITIAL SEED OF SAMPLE CONTENT / IMAGES
------------------------------------------------------------------------------
If you want to populate the database with default showcase data and optimize
sample images into WebP for user @nas:
  sudo docker compose exec backend node src/db/seed.js

------------------------------------------------------------------------------
STEP 4: ACCESS YOUR APPLICATION
------------------------------------------------------------------------------
- Landing Page (Create Profile, Templates, Featured Profiles):
    http://YOUR_SERVER_IP/  (or http://localhost:8080/ if local docker-compose default)

- User Profile URL:
    http://YOUR_SERVER_IP/@nas
    http://YOUR_SERVER_IP/@username

- Visual WYSIWYG Editor:
    http://YOUR_SERVER_IP/@username/edit

- User Login & Registration:
    http://YOUR_SERVER_IP/login
    http://YOUR_SERVER_IP/register
    http://YOUR_SERVER_IP/dashboard

==============================================================================
SAFE UPDATES & MAINTENANCE (HOW NOT TO LOSE DATA)
==============================================================================

Data is persisted in named Docker volumes:
  - Database data -> "pgdata" volume
  - Uploaded images -> "uploads" volume

HOW TO SAFELY UPDATE YOUR CODE:
--------------------------------
1. Pull new code:
     git pull

2. Rebuild and restart containers:
     sudo docker compose up -d --build

(Migrations run automatically on container boot and will NEVER wipe existing data).

==============================================================================
BACKUP & RESTORE PROCEDURES
==============================================================================

[ CREATING A BACKUP ]
1. Database backup:
     sudo docker compose exec db pg_dump -U profile profile > db_backup_$(date +%F).sql

2. Images backup:
     sudo docker compose cp backend:/app/uploads ./uploads_backup_$(date +%F)

3. Environment file backup:
     cp .env .env.backup

[ RESTORING FROM BACKUP ]
1. Restore Database:
     cat db_backup_YYYY-MM-DD.sql | sudo docker compose exec -T db psql -U profile profile

2. Restore Images:
     sudo docker compose cp ./uploads_backup_YYYY-MM-DD/. backend:/app/uploads/

==============================================================================
TROUBLESHOOTING
==============================================================================

1. Check logs if any container fails:
     sudo docker compose logs -f backend

2. Restart containers:
     sudo docker compose restart

3. Reset completely (WARNING: Deletes DB volume):
     sudo docker compose down -v
     sudo docker compose up -d --build
